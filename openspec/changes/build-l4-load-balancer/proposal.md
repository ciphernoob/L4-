# Proposal

## Why

现有项目已经实现基于 epoll 的 Reactor、TCP 连接、定时器和异步日志，但最终形态仍是与 HTTP 业务耦合的教学型 Web 服务器。将这些基础能力整理为一个用户态四层 TCP 负载均衡器，可以集中展示 C++ 网络编程、连接生命周期、并发模型、背压、调度算法和故障处理，并形成一个结构清楚、可测试、适合秋招讲解的完整项目。

## What Changes

- 新增独立的 `l4lb/` CMake 工程，保留 `code/day01` 至 `code/day29` 的历史教程快照不变。
- 从 `day29` 提炼并修复通用网络基础设施，使 TCP 层不再依赖 HTTP，并补齐线程归属、事件启停、错误处理、连接关闭和缓冲区边界行为。
- 新增非阻塞 `Connector`，支持负载均衡器主动连接后端节点。
- 新增 `ProxySession`，将客户端连接和后端连接绑定到同一个工作 EventLoop，透明转发双向字节流，并处理连接建立前缓存、背压、半关闭、错误和超时。
- 新增 Round Robin 与 Least Connections 调度策略，以及包含健康状态、权重和活跃连接数的后端池。
- 新增主动 TCP 健康检查，使用连续成功/失败阈值控制后端摘除与恢复。
- 新增 JSON 配置加载、运行指标、结构化日志、信号处理和优雅退出。
- 新增单元测试、端到端故障测试和基准测试方案，并记录直连后端与经过代理时的吞吐、延迟、CPU 和内存对比。
- 明确首版仅支持 Linux、IPv4 和 TCP；不实现 UDP、TLS 终止、HTTP 路由、动态服务发现、内核态 LVS、DPDK 或 eBPF 数据面。

## Capabilities

### New Capabilities

- `l4-load-balancing`: 定义可配置、多线程的四层 TCP 代理行为，包括后端选择、透明双向转发、背压、半关闭、健康检查、超时、指标和优雅退出。

### Modified Capabilities

- 无。

## Impact

- 新增独立目录 `l4lb/`，包含 `base`、`net`、`lb`、`config`、`app` 和测试代码，不覆盖现有逐日教程源码。
- 构建目标平台为 Linux，继续采用 CMake 和 C++14；复用 pthreads 与 jsoncpp，不引入运行时服务依赖。
- 对外提供一个 TCP 监听端口、JSON 启动配置和只读运行指标；数据面不解析或修改应用层协议。
- 需要重点验证慢客户端/慢后端下的内存上限、连接失败与恢复、跨线程生命周期、半关闭语义以及高并发稳定性。
